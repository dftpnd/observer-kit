# PRINCIPLES — три критерия выбора и записанные решения

Этот документ — арбитр. Если в `ARCHITECTURE.md`, `RESEARCH.md` или `TASKS.md` два варианта,
выбирается тот, который лучше по этим трём критериям в таком порядке приоритета. Спорные места
ниже уже разрешены; новое решение читается здесь, а не в переписке.

## Критерии (по порядку)

1. **Стабильность** — предсказуемость на каждом кадре и после любого патча хоста:
   детерминированный бюджет кадра, цена отказа (бит валидности вместо нулей), отсутствие
   скрытых состояний, приёмка = тест, а не «на глаз».
2. **Масштабируемость** — 100-я фича и новый патч хоста не требуют правки общих файлов:
   одна фича = одна директория, конфиг-ключи объявлены заранее, правила проверки — данные.
3. **Незаметность** — минимум нового профиля в системе хоста: один внешний процесс,
   никаких перехватов/подсадки модулей/патчей кода, чтение пачкой, запись только whitelist convar-ов,
   ввод по умолчанию выключен.

Правило разрешения конфликтов: критерий 1 > критерий 2 > критерий 3. Если решение улучшает
незаметность, но делает поведение кадров нестабильным — оно отвергается.

## Записанные решения (принимаются как окончательные)

| ID | Решение | Почему (критерий) |
|---|---|---|
| P1 | Ядро — **C++20**, один процесс, модульный монолит | Стабильность: детерминированная память без рантайм-границ; Масштаб: контракт = заголовок; Незаметность: один процесс, один профиль |
| P2 | Rust остаётся **только** как внешний готовый дампер (`src-A`), свой парсер Source2 не пишем | Стабильность: не изобретать разбор NetworkStrings; Незаметность: дампер — отдельный привилегированный процесс, живущий 20 секунд на патч |
| P3 | Один артефакт полевых смещений: **`contracts/fields.client-<build>.json`**; старый JSON никогда не правится — новый патч = новый файл | Стабильность: откат и сравнение по файлам; Масштаб: CI пересобирает по cron |
| P4 | `HostState` — **view поверх `FrameArena`** фиксированной ёмкости (`std::span`, без `std::vector`), `parse_frame(RawFrame, OffsetRegistry, FrameArena&)` | Стабильность: ноль аллокаций в кадре ⇒ нет джиттера и фризов на 240 Гц |
| P5 | Корневой `CMakeLists.txt` один раз пишет **T000** и использует `if(EXISTS) add_subdirectory(...)` для всех модулей и фич; позже его не трогает никто | Масштаб: фича не конфликтует с фичей; Стабильность: мердж не может сломать сборку |
| P6 | Ключи конфига для **всех** фич объявляет T021 заранее (`<feature>.enabled` + параметры + диапазон); фича своих ключей не добавляет | Масштаб: новая фича не трогает `config.schema.json`; Стабильность: неизвестный ключ = ошибка, а не молчание |
| P7 | Linux-бэкенд чтения — отдельная директория `src/memory/vm_readv_backend/` со своим `CMakeLists.txt` | Масштаб: ни одной общей записи на двоих |
| P8 | Golden-фикстуры снимаются **одним** прогоном хоста на Windows и коммитятся с `MANIFEST.sha256`; CI на Linux их только проигрывает без хоста | Стабильность: воспроизводимость приёмки; P2: ELF-скана в дампере нет (Q7) |
| P9 | Гигиена профиля: чтение пачкой (1 syscall/кадр), одно окно оверлея, whitelist convar-ов, `sv_cheats` не писать, весь ввод (`combo`) выключен по умолчанию, `is_stale()` останавливает чтение на устаревших смещениях | Незаметность: минимальный профиль; Стабильность: устаревшее смещение не читается вообще |
| P10 | Неизвестное поле = `not-established` + 0 примитивов; угаданное число в код запрещено | Стабильность: ложные данные хуже отсутствия данных |
| P11 | Lua-песочница и DMA-стриминг — вне M0–M7, но интерфейс `SnapshotStream`/`IFeature` их не ломает | Масштаб: новые способы доставки состояния без переделки фич |
| P12 | Терминология: в наших текстах, именах кода, строках вывода, именах файлов и ключах конфига — только слова из `TERMS.md:1`; внешние названия (репозитории, API, convar-ы, цитаты источников) — только в `бэктиках` или кавычках; список запрещённых слов живёт вне рабочей копии, в `../observer-notes/GLOSSARY.md` | Незаметность: ни в тексте, ни в бинарнике нет «говорящих» строк, и в рабочей копии нет словаря чужих слов; Масштаб: словарь один, правится в одном месте |
| P13 | Хост и его мир называются только нашими словами из `TERMS.md:1`: хост, оператор, агент, актор, паж, страж, маяк, воздействие. Настоящие имена модулей и полей семьи движка — литералы в `бэктиках`, они нужны исполнителю; то, в чём имя хоста написано прямо, — только ручка (P14) | Незаметность: ни в текстах, ни в бинарнике нет названия хоста и жанра; Масштаб: словарь один, правится в одном месте (P12) |
| P14 | Идентичность среды хоста живёт **вне** рабочей копии: `../observer-notes/HOST-ENV.json` (ручки `host_bin`, `host_bin_linux`, `version_file`, `patch_current`, `cv.*`, `src-*`, `cache_root`). В репозитории — только ручки: в C++ значения приходят из генерируемого `include/ovr/host_env.hpp` (`OVR_HOST_ENV`), в JSON-контракты — как значения-ручки (`target: "host"`, `patch: "patch_current"`, `toolchain: "src-A"`). Словарь семьи движка (`client.dll`, `engine2.dll`, `sv_cheats`, `r_farz`, `fog_enable`) остаётся дословной цитатой, потому что хоста не выдаёт | Незаметность: ни в дереве, ни в git-истории, ни в бинарнике нет имени хоста; Стабильность: нет файла ⇒ `host_env::is_available() == false`, а не угаданное имя (P10); Масштаб: новая сборка или другой продукт той же семьи = новый HOST-ENV, код не правится |

## Что это значит на практике для исполнителя задачи

- Не хватает ключа конфига, поля дампера или строки в `main.cpp` — ответ «контракт неполон»,
  а не новое имя/новое число (P6, P10).
- Нельзя добавить процесс, поток, перехват, `sleep`, аллокацию в `run()` или литерал смещения (P1, P4, P9).
- Новый файл — только внутри директории своей задачи; общие файлы: `src/main.cpp`
  (две санкционированные строки) и больше ничего (P5).
- Придумал новое слово или имя — сначала строка в `TERMS.md`, потом код (P12).
- Нужна настоящая строка хоста (имя процесса, convar-а, файла версии) — это ручка и `HOST-ENV.json`,
  а не литерал в коде, в JSON или в сообщении коммита (P14).
